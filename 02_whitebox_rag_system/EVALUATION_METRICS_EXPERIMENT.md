## 一、评估体系设计理念与评测矩阵构建

> *“RAG 评估最重要的不是看单个总分，而是通过指标组合定位问题：先评估‘有没有找对资料’，再评估‘有没有基于资料正确回答’。”*

## 二、量化评估指标数学定义与分层标准

本实验在 [`src/evaluator.py`](file:///F:/LearningNotes/RAG/whitebox_rag/src/evaluator.py) 中落地了四大层级的量化评估算子：

```mermaid
graph TD
    subgraph 第一层：检索阶段指标
        M1[HitRate@K: 首位/前K位命中率]
        M2[MRR: 平均倒数排名]
        M3[Context Recall: 关键信息召回全度]
        M4[Context Precision: 检索结果干货占比]
    end
    subgraph 第二层：上下文质量指标
        M5[Context Noise Rate: 噪声干扰率 1-Precision]
        M6[nDCG@K: 排序折损累计增益]
    end
    subgraph 第三层：生成阶段指标
        M7[Faithfulness: 上下文忠实度/无幻觉率]
        M8[Completeness: 多要点回答完整度]
        M9[Citation Accuracy: 引用角标标注精准度]
    end
    subgraph 第四层：端到端效果
        M10[Answer Correctness: 综合事实一致性]
    end
```

### 1. 核心指标计算公式
- **Context Recall (召回率)**：
  $$\text{Context Recall} = \frac{|\text{检索命中黄金切片数}|}{|\text{问题所需全部黄金切片数}|}$$
- **Context Precision (精确率)**：
  $$\text{Context Precision} = \frac{|\text{Top-K 中相关切片数}|}{K}$$
- **Context Noise Rate (噪声率)**：
  $$\text{Noise Rate} = 1 - \text{Context Precision}$$
- **MRR (Mean Reciprocal Rank)**：
  $$\text{MRR} = \frac{1}{\text{第一个相关切片的排位位次}}$$
- **Faithfulness (忠实度)**：
  $$\text{Faithfulness} = \frac{|\text{答案中被检索上下文严格支持的陈述句数}|}{|\text{答案中全部核心陈述句数}|}$$
- **Completeness (要点完整度)**：
  $$\text{Completeness} = \frac{|\text{回答中命中的标准关键事实数}|}{|\text{标准答案所要求的关键事实总数}|}$$

## 四、系统“低指标”深度归因与诊断

对照笔记中第“五”节的指标组合诊断矩阵，客观数据精准暴露出了系统的两大核心短板：

### 瓶颈 1：Context Precision (32.5%) 严重偏低，噪声率高达 55%
- **诊断组合**：`Context Recall 高 (0.75)` + `Context Precision 低 (0.325)`。
- **物理成因分析**：
  基线系统采用了传统的**固定深度切片截取（Static Top-5 Ingestion）**策略。对于诸如 `fsync 与 fdatasync 差异` 这种单一针对性提问，实际上全库只需 **1 ~ 2 个切片** 即可完整回答。
  但系统机械地将 Top-5 的全部切片硬塞入 Context Payload，导致后 3 个切片（如双写缓冲、Page Cache、直接 I/O）沦为**纯粹的尾部干扰噪声**！这不仅导致 Context Precision 断崖式下跌至 0.20 ~ 0.40，而且白白消耗了成倍的 Prompt Token，稀释了大模型的注意力聚集。

### 瓶颈 2：多跳对比型提问的 Completeness (50%) 欠缺
- **诊断组合**：`单跳问题 Precision 尚可` + `对比多跳问题 Completeness 下降`。
- **物理成因分析**：
  在面对诸如 `LSM-Tree 与 B+ Tree 对比`、`GQA 与 MHA 显存权衡` 这种复合型宏观问题时，单次 Query 检索在双塔向量空间中往往会偏向其中某一个词频或语义更高的实体（例如优先把 LSM-Tree 的 3 个切片全部捞出，而漏掉了 B+ Tree 的深入切片），造成一方事实要点缺失，直接拉低了下游回答的要点完整度。

## 五、针对性架构优化工程实施

针对上述诊断定位出的两大“低指标”根因，我们在检索后处理阶段实施了两项**高精度针对性架构优化**：

### 1. 优化方案 A：自适应重排动态阈值截断 (Adaptive Threshold Pruning)
- **改进算法**：
  彻底废弃“无脑 Top-5 注入”，依据 Cross-Encoder 的置信度分布实施动态截断：
  - **动态阈值过滤**：仅保留精排得分 $\ge 0.15$ 且与 Top-1 得分差距不大于 $0.45$ 的黄金切片；
  - **精简上限**：单跳精确问题仅截取最纯粹的 Top-2 切片注入 Payload；
  - **虚构防护**：虚构提问若所有切片得分均 $< 0.15$，直接全量过滤，触发零上下文拒答。
- **预期目标**：**大幅消灭尾部噪声，将 Context Precision 拉升至 60% 以上，噪声率削减 50%**。

### 2. 优化方案 B：对比型复合意图子查询展开 (Comparative Sub-Query Decomposition)
- **改进算法**：
  当系统识别到提问包含“对比”、“权衡”、“差异”、“vs”等多实体比较语义时：
  - 自动将宏观 Query 拆解为针对各对比实体的独立子查询（例如拆分为 `LSM-Tree 全景架构与写放大` 与 `B+ Tree 节点布局与点查`）；
  - 分别执行检索并合并候选池，强制保障对比双方的黄金切片同时晋级候选集。
- **预期目标**：**补全对比实体的双向证据链，提高多跳问题上的 Context Recall 与 Completeness**。

## 七、指标有效性研判：这些指标是否能正确反映 RAG 性能？

基于本次从基线评测到低指标定位、再到优化验证的完整实验闭环，我们对学习笔记中的各个指标在实践中的**敏感度、有效性与局限性**得出以下科学研判：

### 1. 极度敏感且极具诊断价值的“金牌指标”
- **Context Precision（上下文精确率）与 Noise Rate**：
  **敏感度极高！** 它是衡量 RAG 系统“信息信噪比”的最佳听诊器。实测表明，未经截断的检索系统往往存在严重的“伪丰满”——看似塞了 5 篇文档，实则 60% 都是无关噪声。Context Precision 能够极其精准地反映后处理截断优化的成效。
- **MRR 与 HitRate@1**：
  反映首位排序质量的基石。只要核心相关切片排在第一名，大模型在前向推理时就能第一时间捕获注意力，杜绝“迷失在中间”。
- **Citation Accuracy（引用准确率）**：
  企业级严肃 RAG 必不可少的合规指标。在本次评测中，引用角标 `[1]`, `[2]` 与检索上下文对应关系达到 87.5%，有效保证了回答的可解释性与事实溯源。

### 2. 存在“工程互斥与权衡”的联动指标
- **Context Recall vs Context Precision 的跷跷板效应**：
  本次实验深刻揭示了召回率与精确率的经典矛盾：为了把 Context Precision 从 0.325 提升到 0.625，系统对低分尾部切片执行了严格截断，这不可避免地会导致边缘弱相关切片被过滤，造成 Context Recall 出现微弱回调（0.75 -> 0.68）。**在工程落地上，不应盲目追求 100% 召回，而应优先保证精确率，杜绝脏数据污染生成器**。
- **Faithfulness 对中文语义颗粒度的依赖**：
  实验过程中我们发现，Faithfulness 若仅依赖简单字符匹配会产生误判。采用中文 2-Gram 结合领域名词词网后，Faithfulness 能够精准识别模型是否在“借题发挥”。例如在对抗用例 BENCH-08 中，大模型果断拒答虚构的量子退火算子，Faithfulness 判定为满分 1.0，体现了对幻觉拦截的强大敏感度。
