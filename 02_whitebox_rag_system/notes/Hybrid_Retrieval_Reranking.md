# RAG 混合检索与重排序机制 (Hybrid Retrieval & Reranking)

## 1. 混合检索 (Hybrid Retrieval)
当前主流的检索技术采用混合检索机制，用于扩大召回率：
- **稀疏向量检索**（如 BM25，基于关键词/词频匹配）
- **稠密向量检索**（如 Embedding 模型，基于语义匹配）
两者并行搜索，分别从全量知识库中获取各自的 Top-K 候选文档。

## 2. 结果融合 (Result Fusion)
将两路召回的候选文档进行合并与初步排序。
- **常用算法**：倒数排名融合 (Reciprocal Rank Fusion, RRF)。
- **原理**：不依赖于各自的具体相似度分数（因为稀疏分数和稠密分数分布差异大，难以直接相加），而是根据文档在不同检索方法中的“排名名次”的倒数之和，来计算一个综合得分，从而得到一个合并后的粗排候选集合（如 Top-N）。

## 3. 重排序 (Re-ranking)
在得到融合后的 Top-N 候选集后，为了提升最终的准确率 (Precision)，进行精排。
- **核心机制**：通常采用**交叉编码器 (Cross-Encoder)**。
- **交互方式**：将 Query 和 **单个** 候选文档拼接为一个单一序列（例如 `[CLS] Query [SEP] Document_A [SEP]`），输入到 Transformer 网络中。通过全注意力层 (Full Self-Attention) 进行深度的词级别 (Token-level) 交互，计算出极高精度的语义对齐得分。
- **结果输出**：根据交叉编码器的得分重新对这 N 个文档进行绝对排序，截取最终的 Top-K 最相关文档，直接嵌入 Prompt 供后续 LLM 使用。

---
## ⚠️ 常见误区与避坑指南

1. **术语混淆**：融合算法叫“倒数排名融合 (RRF)”，利用的是排名的倒数（1/rank）；不要将其与全文检索中的数据结构“倒排索引 (Inverted Index)”混淆而称为“倒排名”。
2. **重排序的认知误区**：重排序**绝对无法**找回在第一阶段（召回阶段）就落榜排在极低的文档。因为交叉编码器的计算复杂度过高（$O(N^2)$ 的注意力计算），它只能在已经召回的 Top-N 集合内进行精排。如果因为单一方法的缺陷导致某文档未进入召回候选集，重排序阶段根本看不见它，不可能对其进行挽救。挽救极端低排名文档的任务属于第一阶段的“多路召回”策略，而非重排序阶段。
3. **输入机制误区**：重排序时，不是将多个文档“融合”后输入模型，而是 Query 与每一个候选文档**逐一配对**输入进行独立打分，然后根据分数进行重新排序。
